# Contributing

Thanks for helping improve `contentful-core.php`.

## Development with Dev Containers

This repository includes a `.devcontainer` configuration for a reproducible local setup. GitHub Actions uses the same devcontainer configuration for CI.

### Visual Studio Code

Open the repository in Visual Studio Code, install the Dev Containers extension if needed, then run `Dev Containers: Reopen in Container`. Wait for the container build and post-create setup to finish.

### Terminal or other editors

Install Docker and the Dev Container CLI (`npm install -g @devcontainers/cli`). From the repository root, run:

```bash
devcontainer up --workspace-folder .
devcontainer exec --workspace-folder . bash
```

### Verify the environment

```bash
composer test-quick-fail
```

## All Available Commands

Sourced from `composer.json` scripts:

| Command | What it does |
|---|---|
| `composer run test` | Run the full PHPUnit test suite |
| `composer run test-quick-fail` | Run tests, stop on first error or failure (`--stop-on-error --stop-on-failure -v`) |
| `composer run test-for-bc-breaks` | Check for backwards-compatibility breaks against the previous release using `roave/backward-compatibility-check` |
| `composer run lint-static-analysis` | Run PHPStan static analysis on `src/` at level 5 |
| `composer run release` | Run the release helper script (`scripts/release.php`) — maintainers only |

## Testing

- **Framework:** PHPUnit ^8.5
- **Config:** `phpunit.xml.dist`
- **Test location:** `tests/Unit/` (mirrors `src/` namespace structure)
- **Fixture JSON:** `tests/Fixtures/Unit/`
- **Concrete test implementations:** `tests/Implementation/` — test-only subclasses of abstract library classes

```bash
# Run all tests
composer run test

# Run and stop on first failure
composer run test-quick-fail
```

## Static Analysis

PHPStan at level 5:

```bash
composer run lint-static-analysis
```

Fix reported issues and commit before opening a PR.

## Backwards Compatibility

This library enforces backwards compatibility via `roave/backward-compatibility-check`:

```bash
composer run test-for-bc-breaks
```

This check runs in CI against git history (`fetch-depth: 0` required). Any breaking changes require a **major version bump** — dropping a PHP version counts as breaking.

## CI/CD

All CI runs inside the devcontainer (same image as local dev). GitHub Actions jobs:

| Job | Trigger | What it does |
|---|---|---|
| `lint-syntax` | push/PR to `master` | Runs `php -l` on all PHP files (PHP 8.1 container) |
| `static-analysis` | push/PR to `master` | Runs `composer run lint-static-analysis` |
| `backwards-compatibility` | push/PR to `master` | Runs `composer run test-for-bc-breaks` |
| `test (matrix)` | push/PR to `master` | Runs `composer run test-quick-fail` across PHP 8.0, 8.1, 8.2, 8.3, 8.4 |

## Branch Strategy

- `master` — stable branch; all releases are tagged from here
- Feature/fix branches — `feat/`, `fix/`, `chore/`, `docs/` prefixes, merged via PR
- Conventional Commits format: `feat:`, `fix:`, `chore:`, `docs:`, etc.

## Release Process

Releases are manual (maintainers only). High-level steps:

1. Open a PR with updated `CHANGELOG.md` and version bump; get human approval + CI green
2. Merge to `master` via `gh pr merge --merge`
3. Run `composer run lint-static-analysis` and php-cs-fixer locally; commit any fixes
4. Tag the release: `gh release create <version> --repo contentful/contentful-core.php --title "<version>" --notes "<CHANGELOG entry>"`
5. Verify the Packagist webhook fires; manually trigger sync if needed
